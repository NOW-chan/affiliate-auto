# 比較・解説型アフィリエイト記事の作り方

CLAUDE.md の「絶対ルール」と「HTML の書き方」を必ず先に読み、すべて守ること。

## 手順

1. **案件を読む**：`cases.yaml` から指定された `id` の案件を読む（name / link / official_url / genre / angle / target / competitors）。
2. **公式情報を集める**：`official_url` を WebFetch し、料金・プラン・特徴・注意点・確認日をメモする。
   `competitors` があれば、それぞれの公式サイトも確認する（最大3社）。確認できなかった項目は「公式サイトで要確認」とする。
3. **読者を決める**：`target` に書かれた読者の悩みを1文にまとめ、記事の冒頭で共感→解決の流れを作る。
4. **構成**（目安 4,000〜6,000字）
   - PR表記（最初の要素）
   - 導入：読者の悩み → この記事でわかること（3点）
   - 結論ボックス：どんな人に向いている／向いていない
   - サービスの概要（公式情報ベース、確認日つき）
   - 比較表：対象サービス＋競合（料金・特徴・向いている人）
   - メリット／注意点（注意点も必ず書く。公平さが信頼につながる）
   - 選び方のポイント（3つ）
   - よくある質問（3〜5問、公式FAQの範囲で）
   - まとめ＋CTAボタン（アフィリエイトリンク）
   - 著者プロフィール
5. **HTML を書く**：`articles/<id>/article.html`
   - CTA は本文中に2〜3か所まで
   - 比較表はスマホで横スクロールできるようにする（`.nowc-article .table-wrap { overflow-x: auto; }`）
6. **meta.yaml を書く**：`articles/<id>/meta.yaml`
   ```yaml
   title: "（32字前後。検索されそうな語を前半に）"
   description: "（120字以内の要約）"
   categories: ["PR", "（ジャンル名）"]
   ```
7. **セルフチェック**（全部 Yes になるまで直す）
   - [ ] 最初の要素が `<p class="nowc-pr">【PR】…</p>` になっている
   - [ ] 一人称の利用体験が1つもない
   - [ ] 数値・料金に確認日と出典がある
   - [ ] すべてのCSSセレクタが `.nowc-article` から始まる
   - [ ] アフィリエイトリンクに `rel="sponsored nofollow noopener"` と `target="_blank"` がある
   - [ ] 誇大表現・効果効能の断定がない
   - [ ] 著者プロフィールが末尾にある

## やってはいけないこと

- `cases.yaml` や `scripts/` を編集する
- 画像を外部から引用する
- 公式サイトにない情報（口コミ・数値・ランキング）を作る
